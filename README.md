# Credit Card Fraud Detection Using Machine Learning

An end-to-end **CRISP-DM** educational portfolio project comparing Logistic Regression and Random Forest on an imbalanced credit-card transaction dataset.

## Motivation and questions

Fraud is rare, so accuracy can be misleading. This project asks: How common is fraud? How do transaction amounts vary? Which model best balances recall and precision? What does a prediction on a held-out transaction mean?

## Dataset

[Credit Card Fraud Detection (ULB/Worldline, Kaggle)](https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud). The published dataset has 284,807 transactions and 492 fraud cases. Anonymized features V1–V28 prevent attributing patterns to specific merchants or customers.

**Download required:** Place `creditcard.csv` in `data/`. The CSV is not included in this repository. The notebook cannot produce verified model results until the dataset is supplied and cells are executed.

Python, pandas, NumPy, Matplotlib, Seaborn, scikit-learn, and JupyterLab.

## Methods and evaluation

Exact duplicates and missing records are removed, then data is stratified into 80% training and 20% testing. Scaling is fitted only on training data in the Logistic Regression pipeline. Both models use class weighting. Evaluation includes accuracy, precision, recall, F1, ROC AUC, average precision (PR AUC/AP), confusion matrices, and precision–recall curves.

## Limitations

Single stratified holdout, historical observations, anonymized PCA features, no cost-sensitive threshold optimization, no calibration, and no temporal drift validation. This is not a production fraud engine.
